  <action>
    1. Define src/gem_api/rules/models.py:
       - ResultState enum: PASS, FAIL, REVIEW, UNVERIFIABLE
       - ActionOverrides model: on_fail: Optional[ResultState], on_missing: Optional[ResultState], on_portal_down: Optional[ResultState]
       - CheckConfig model: id: str, type: str, params: dict[str, Any] = {}, overrides: Optional[ActionOverrides]
       - RequirementConfig model: id: str, description: str, mandatory: bool = True, applies_if: Optional[dict[str, Any]] = None, evidence_types: list[str], checks: list[CheckConfig]
       - TenderRuleConfig model: tender_id: str, version: str, rule_set_version: str, tender_category: str, estimated_value: Optional[float] = None, local_content_threshold: Optional[float] = None, requirements: list[RequirementConfig]
       - VerificationContext model: tender: dict[str, Any], bidder: dict[str, Any], evidence: dict[str, Any], portal_results: dict[str, Any]
       - CheckResult model: check_id: str, state: ResultState, message: str, details: dict[str, Any] = {}
       - RequirementEvaluation model: requirement_id: str, state: ResultState, check_results: list[CheckResult], is_applicable: bool
    2. Implement src/gem_api/rules/loader.py:
       - load_tender_rules(yaml_path_or_str: str) -> TenderRuleConfig.
       - Validates with fail-fast exception handling if invalid syntax or schema mismatch.
    3. Create sample YAML configs in config/tenders/:
       - sample_goods.yaml: Goods tender requiring GSTIN, PAN, Make in India threshold (50%).
       - sample_services.yaml: Services tender requiring GSTIN, PAN, and conditional EPFO/ESIC (`applies_if: { tender_category: "services" }`).
    4. Write tests/unit/test_rules_config.py verifying valid parsing, invalid schema rejection, and fail-fast startup behavior.

  <action>
    1. Implement src/gem_api/rules/registry.py:
       - CHECK_REGISTRY dictionary mapping check type strings to callable functions.
       - @register_check(name: str) decorator to register pure check functions.
       - get_check_handler(name: str) returning handler or raising UnknownCheckError.
    2. Implement src/gem_api/rules/builtins.py:
       - @register_check("format_gstin"): runs gstin validator on evidence.
       - @register_check("format_pan"): runs pan validator on evidence.
       - @register_check("format_udyam"): runs udyam validator on evidence.
       - @register_check("cross_check_gstin_pan"): runs GSTIN-PAN cross check.
       - @register_check("certificate_validity"): checks cert date against context.tender.bid_opening_date.
       - @register_check("make_in_india_threshold"): verifies local content >= tender threshold; returns FAIL on deficiency.
       - @register_check("debarment_check"): checks bidder against debarment records considering scope (organization-wide, category, and time bounds).
    3. Implement src/gem_api/rules/engine.py:
       - is_requirement_applicable(req: RequirementConfig, context: VerificationContext) -> bool: matches context dict against req.applies_if key-values.
       - evaluate_requirement(req: RequirementConfig, context: VerificationContext) -> RequirementEvaluation.
       - evaluate_tender(config: TenderRuleConfig, context: VerificationContext) -> list[RequirementEvaluation].
       - Enforces default state rules: FAIL on check false, REVIEW on missing evidence, UNVERIFIABLE on portal outage, with overrides applied when present.
    4. Write comprehensive tests in tests/unit/test_rules_engine.py covering each builtin check, applicability conditions, and full tender evaluation.
  </action>

    - Non-applicable requirements are correctly skipped with is_applicable=False
